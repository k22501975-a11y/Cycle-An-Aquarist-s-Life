## 1. 一句話概念

**從一個小缸開始的養魚愛好者，用真實的養魚知識把魚養好、繁殖，培育出稀有品種，在玩家市場上賣錢，再用賺到的錢擴缸。**

- 名稱：App 與商店用英文「Cycle: An Aquarist's Life」，桌面短名「Aquarist's Life」（2026-10-19 YenWel 決定；遊戲內文字維持繁中）。中文「水族人生」只當暱稱 ✅
  - Cycle 雙關：Nitrogen Cycle（氮循環）＋ Life Cycle（生命循環）
  - 上架前需再查 Google Play / App Store / 商標是否撞名（已知同題材遊戲《Aquarist》，須區隔）
- 類型：經營模擬 ＋ 硬核生態模擬 ✅
- 平台：手機（Android + iOS），需要連線 ✅

## 2. 核心設計原則

1. **跟真實世界養魚一樣** ✅：水質、氮循環、疾病、繁殖都以現實為依據。
2. **沒養好會生病、會死** ✅：這是最重要的體驗。
3. **死亡必須有原因可循**：玩家事後能明白「是我哪裡做錯」，不能是隨機懲罰。
4. **稀有度來自遺傳與選育，不是抽卡**：稀有魚代表玩家的技術與耐心。
5. **生態與經濟綁在一起**：養得好才繁殖，繁殖才賺錢。

## 3. 玩家身分與成長路線 ✅

- 玩家是**自己在家養魚的愛好者**，從一個小缸起步，逐步擴充到多缸。
- 目標玩家：真的有在養魚、在意寫實度的人。
- 長期目標：賺錢、賣魚，**越稀有賣越多錢**；擴缸、選育品系、收集品種。

### 核心循環

```
養水 → 放魚 → 照顧（餵食、換水、監測）→ 繁殖 → 選育
  ↑                                              ↓
  └──── 擴缸 / 買設備 ← 賺錢 ← 在玩家市場賣魚 ←───┘
（任何環節出錯 → 壓力 → 生病 → 死亡 → 連鎖崩潰）
```

## 4. 時間系統

- **基準倍率：現實 1 天 = 遊戲 1 週（7 倍速）** 💡（建議採用）
- **倍率必須是伺服器端設定參數，不可寫死** ✅；所有玩家時間同步（交易、合作繁殖需要）。

| 項目 | 真實時間 | 7 倍速下 |
|---|---|---|
| 每週換水 | 1 週 | 每天一次（= 每日上線維護） |
| 每天餵食 1–2 次 | 1 天 | 每 2–3 小時 |
| 睡覺 8 小時 | — | 遊戲過約 2.3 天 |
| 氨中毒致命 | 數小時 | 約 1–2 小時 |
| 新缸養水 | 4–6 週 | 4–6 天 |
| 孔雀魚懷孕 | 約 4 週 | 約 4 天 |
| 小魚長到可繁殖 | 約 3 個月 | 約 2 週 |
| 孔雀魚壽命 | 約 2 年 | 約 3.5 個月 |

- 漏餵幾次不會立刻死：飢餓是漸進的（變瘦、壓力上升）。
- **急性危機**（停電、加熱棒故障、疾病爆發）發展速度要放慢，保留現實數小時的反應時間，並搭配推播預警。💡

## 5. 生態模擬系統

### 5.1 氮循環（核心骨幹）

```
排泄物 + 殘餌 + 死魚屍體
      ↓ 分解
   氨 NH₃（劇毒）
      ↓ 亞硝化菌（長在濾材上，繁殖慢）
   亞硝酸鹽 NO₂（有毒）
      ↓ 硝化菌
   硝酸鹽 NO₃（低毒，累積，只能靠換水移除）
```

必須能自然產生的情境：
- **新缸症候群**：細菌未建立就放太多魚 → 氨爆。
- **過度餵食**：殘餌腐敗 → 水質惡化。
- **洗濾材陷阱**：用自來水洗濾材會殺死細菌群落。
- **用藥副作用**：抗生素也會殺死硝化菌。
- **濾材接種**：從成熟缸取得濾材可加速養水（可作為好友互贈的社交功能）。

### 5.2 其他水質參數

- 溫度（加熱棒可能故障、停電）
- pH 與 KH（KH 緩衝耗盡時 pH 會崩跌）
- 溶氧（水溫越高溶氧越低；魚越多耗氧越快）

### 5.3 魚種屬性

每個品種需定義：
- 適溫範圍、適合 pH / 硬度範圍
- 成魚體型、生物負載（排泄量）
- 性格：攻擊性、是否群游（及最少數量）、是否咬鰭
- 體質強弱、壽命、成熟時間、繁殖方式與週期
- 遺傳性狀（見第 6 節）

### 5.4 壓力 → 免疫 → 疾病

```
壓力來源：參數超出範圍、參數變化太快（未對水）、過度擁擠、
          被欺負、飢餓、群游魚數量不足、運輸
      ↓ 累積
   壓力值 ↑ → 免疫力 ↓
      ↓
感染機率 = 環境病原量 × (1 − 免疫力)
```

病原來源：新魚未檢疫、水質髒污、病魚傳染。

### 5.5 疾病（第一批）

| 疾病 | 主要成因 | 特性 |
|---|---|---|
| 白點病 | 溫度驟變、新魚帶入 | 傳染性強；提高水溫可加速治療 |
| 爛鰭病 | 水質差 | 早期好治，拖久惡化 |
| 氨中毒 | 氨濃度過高 | 中毒非疾病；大量換水解決 |
| 黴菌感染 | 受傷後繼發 | 與打架、咬鰭連動 |
| 腹水病 | 長期壓力 | 晚期幾乎無法治癒 |

> 疾病的實際參數（潛伏期、病程、致死率、藥效）需另外研究真實資料再定。

### 5.6 症狀與診斷（玩家當獸醫）

症狀分階段出現：
1. **行為異常**（早期）：躲藏、鰭收縮、摩擦身體、浮頭喘氣、食慾下降
2. **外觀變化**（中期）：白點、鰭緣破損、棉絮狀物、鱗片豎起
3. **瀕死**（晚期）：側翻、失去平衡

- 水質數值需購買**測試劑**才看得到。
- 玩家自行判斷病因、選擇藥物；用錯藥浪費錢、增加魚的負擔、可能傷害蝦與水草。

### 5.7 死亡與連鎖反應

- 健康歸零即死亡。
- **死魚未撈出會腐爛產生大量氨** → 其他魚中毒 → 壓力上升 → 接連生病 → 可能整缸崩潰。

### 5.8 設備、水草與光照 ✅（2026-10-18 討論）

> **水草是與養魚並列的第二條核心玩法** ✅：玩家可以專心養草、造景，修剪下來的草可以繁殖、在市場上賣（稀有草或特殊變異也有高價），參觀功能展示造景缸。

**設備**
- 缸子大小：水量決定稀釋速度（同樣排泄量，小缸氨升得更快）。
- 容量不寫死隻數：生物負載（各魚排泄量 × 數量）對比水量與過濾能力，超載 → 擁擠壓力。
- 過濾器：流量 + 濾材面積 → 硝化菌上限與處理速度（海綿 / 外掛 / 圓桶）。
- 加熱棒：功率需配合水量，可能故障。打氣機：影響溶氧。

**水草**
- 吸收氨與硝酸鹽（天然過濾）；白天光合作用產氧、晚上耗氧；枯萎腐爛會產生氨。
- 分**陰性草**（低光、低 CO2 需求，長得慢，如莫絲、榕類、鐵皇冠）與**陽性草**（高光、高 CO2，長得快，如有莖草、前景草）。
- 生長受「最短板」限制（光、CO2、養分取最低者）。
- 不匹配的後果：陰性草放強光 → 葉面長藻；陽性草光或 CO2 不足 → 徒長、溶葉。

**燈光**
- 參數：光照強度（PAR 概念）與每日照明時數。
- 光太強或太久、但 CO2 / 養分跟不上 → 長藻。

**CO2**
- 加速水草生長，但會降低 pH；KH 低時 pH 跌更快。
- 過量 → 魚缺氧、浮頭。需要打氣與 CO2 之間的平衡（如夜間關 CO2）。

## 6. 繁殖與遺傳 ✅（方向已定）

- 稀有度由**基因**決定（顏色、鰭型等），參考孔雀魚、鬥魚、米蝦、七彩神仙的真實品系。
- 玩家挑選親魚，一代代篩選穩定品系；偶爾出現突變。
- **只有水質穩定、壓力低的魚才願意繁殖**。
- 不同魚種繁殖速度差異大：孔雀魚、米蝦快且便宜（新手賺第一桶金）；七彩神仙等慢且難（高價魚）。
- 新手引導 💡：開局可買到已懷孕的母孔雀魚，幾天內看到第一批小魚。

> 遺傳模型（孟德爾遺傳、多基因性狀、突變率）需另外設計。

## 7. 經濟與市場 ✅（交易是遊戲核心）

- 收入：在**玩家交易市場**賣魚與**水草**（修剪下來或繁殖出的草），越稀有越值錢（也可考慮 NPC 收購作為價格底線 💡）。
- 金錢消耗：電費、飼料、藥品、測試劑、設備購買與維修、擴缸。
- 生病與死亡是天然的魚隻回收機制，防止稀有魚氾濫、價格崩盤。
- **運輸壓力**：買來的魚到貨時處於緊迫狀態、可能帶病；**檢疫缸**因此有價值。
- **賣家信譽**：常賣病魚會降低評價。

## 8. 社交功能 ✅

- **玩家交易市場**（核心）
- **互相參觀**：展示造景缸與稀有魚，兼作商店櫥窗
- **合作繁殖**：把親魚借給朋友配對；魚可能在對方缸裡生病或死亡（信任與風險）
- 好友互贈成熟濾材 💡、互贈水草（修剪或繁殖出的草）✅
  - 贈送有**每日限額**（防止開小號洗資源、繞過市場）✅；額度數字為伺服器端參數 ❓

## 9. 設備與自動化進程 💡

玩家角色從「每天餵魚的人」轉變成「規劃系統的人」：

- **初期**（約前 1–2 週）：基本設備，手動餵食、換水，只能養少量好養的魚
- **中期**：自動餵食器、更大的過濾器、控溫器、自動補水
- **後期**：滴定幫浦、自動換水系統、水質監測器（推播警報）、備用電源

出問題的原因變成**規劃失誤**（餵食量設定太多、過濾不足、密度過高），而非「忘記上線」。

## 10. 離線處理 💡

- 健康的缸在睡覺期間（遊戲約 2.3 天）應該撐得住。
- 狀況惡化時發推播預警，給玩家介入機會。
- 提供「旅行模式」或自動化設備讓玩家事先準備。

## 11. 技術架構 ✅（方向已定）

### 平台與發布

| 平台 | 方式 |
|---|---|
| Android | Capacitor 打包成 **APK**，直接提供下載 |
| iOS | **PWA**（Safari 加入主畫面，免 Mac、免蘋果年費）；之後可用 Capacitor 打包走 TestFlight / App Store |
| 電腦 | 瀏覽器直接玩（方便開發測試） |

> 注意：Google 的 Android 開發者身分驗證 2027 年起全球適用於側載 APK，屆時需完成驗證。

### 技術棧

- **前端**：TypeScript + PixiJS（2D 渲染）+ Capacitor
- **後端**：Java Spring Boot（REST API；需要即時功能時再加 WebSocket）
- **資料庫**：PostgreSQL
- **部署**：VPS 或 Fly.io / Railway 類平台

```
手機（TS + PixiJS；Capacitor → APK / iOS 用 PWA）
        │  HTTPS (REST)，之後視需要加 WebSocket
        ▼
Spring Boot API ── PostgreSQL（帳號、水缸、魚、基因、交易）
```

### 伺服器權威（防作弊）✅

- 每條魚的**基因與身分由伺服器產生與保管**。
- 模擬的關鍵結果（存活、繁殖、後代基因）由伺服器計算或驗證。
- 時間倍率與遊戲時鐘由伺服器統一。
- 實作（L2，2026-10-19）：模擬跑在 Spring Boot 旁的 Node 小服務（同一份 TypeScript），負責離線補算、上傳存檔檢查（時鐘、魚的身分）、市場上架的魚以伺服器那份為準；細節見 server/README.md。

### 手機體驗

- 觸控：點擊投餵、拖曳魚、雙指縮放；按鈕夠大
- 省電：閒置時降幀（例如 30fps）
- 推播：危機預警、繁殖、到貨等通知

## 12. 開發路線（建議分階段）💡

**Phase 0 — 單機原型（驗證好不好玩）**
- 一個水缸、氮循環、三種魚、白點病 + 氨中毒
- 時間加速（開發用可調倍率）、餵食、換水、測試劑
- 魚的游動 AI（Boids + 漫遊 + 碰壁轉向）
- 本機存檔

**Phase 1 — 單機深度**
- 完整水質參數、更多魚種與疾病、症狀與診斷、用藥
- 死亡連鎖、繁殖與基礎遺傳、設備系統、多缸

**Phase 2 — 後端與帳號**
- Spring Boot + PostgreSQL、帳號、雲端存檔
- 模擬與基因移到伺服器權威、離線期間的模擬計算

**Phase 3 — 社交與市場**
- 交易市場、運輸壓力、賣家信譽、參觀、合作繁殖、推播

**Phase 4 — 發布**
- Capacitor 打包 APK、PWA 設定、iOS 測試
